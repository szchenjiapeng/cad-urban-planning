# 子技能 N1：用地面积测算与土地利用规划平衡表

## 触发条件

用户提出下列任一诉求时进入本工作流：

- 算用地面积、统计地块面积、总图算量、按图层统计面积；
- 出用地平衡表、土地利用规划平衡表、用地结构分析；
- 要居住/公服/商业/工业/道路/绿地的占比或人均面积；
- 给了 CAD 图纸（DWG/DXF）要求分析其中的用地构成。

不适用：建筑面积测算（需读 SOLID/HATCH 并区分层数）、土方计算、市政管网算量。

## 四阶段流程

### 阶段 1：确认数据源

先跑 `scripts/cad_env_check.py`，再决定通道：

| 探测结果 | 动作 |
| --- | --- |
| `com: true`（CAD 正在运行） | 直接 `--source com` 连活动图纸，可顺带写回标注 |
| `com: false` + `cad_installed: true` | 不加 `--file` 直接跑，脚本会自动启动已安装的 CAD（首次约 10–30 秒）；不希望弹窗时加 `--no-start-cad` 并改提供 DXF |
| 用户给了 `.dxf` 路径 | `--file` 走 DXF 解析（显式文件优先于 CAD 当前图） |
| `cad_installed: false` | 必须 `--file`；用户只有 DWG 时要求另存 DXF |
| `ezdxf` 缺失 | 提示 `python -m pip install ezdxf`，等用户确认后再继续 |

必须一次问清的信息（缺了会影响结果可信度，但不要逐条盘问，可合并成一句）：

1. 图纸文件路径或「是否已在本机 CAD 中打开」；
2. 规划范围总面积（公顷）——用于覆盖率校验；
3. 人口规模（人）——只有需要人均指标时才问；
4. 分类口径：默认 2023 指南。**发现图层用旧代码（R2/B1/A33/S1…）时必须问**：是否按 GB 50137 统计并换算为 2023？换算用 `--standard gb50137 --convert-to 2023`，不换算则 `--standard 2023`。

不要问的：图层怎么命名（自己看 `--list-layers` 结果）、什么是闭合多段线（这是技能内部知识）。

#### 规划范围的处理顺序

1. **先自动识别**：图层名含 `规划范围线 / 规划范围 / 用地范围 / 规划界线 / 用地界线 / 总用地 / 红线 / 范围线 / 范围 / GHFW(ghfw) / fwx / fw / range / boundary`（忽略大小写）。
2. **命中多个图层** → 脚本输出 `scope_layer` 确认项（退出码 3）。把每个图层的「闭合多段线数 / 多段线数 / 填充数」给用户看，让用户选，**不要自己挑**。用户说「都不是」时，请用户给图层名，重跑加 `--scope-layer "图层名"`（不要求图层名含关键词）。
2.1 **选定图层后看 `decision`**（`--scope-layer "X" --list-scope` 的输出）：`continue` = 只有 1 条闭合多段线，**直接进测算**；`ask_draft` = 多条，**先问有没有未删除的草稿**（有草稿只保留面积最大的一条）；`ask_scope_layer` = 没有闭合线，换图层/先闭合/给范围线文件。
2.2 **非草稿再多条时按空间关系处理**：相离 → 并集；A 在 B 内 → 挖空（统计两环之间）；相邻（仅共边）/ 交叉（有面积重叠）→ 视为绘图问题中断，提示“没合并成一条闭合线”“草稿残留或重复描图”。
3. **识别不到**（或用户否认系统判断的图层里有真实范围线）→ 脚本输出 `scope_not_found` 确认项。此时按三选一处理：
   - 用户给图层名 → `--scope-layer`；
   - 用户说没有规划范围 → 走第 4 步；
   - 用户提供的图层里没有闭合多段线 → 提示先在 CAD 中闭合或改用范围线文件。
4. **向用户索取范围线文件前，必须先原样发出这段要求**（不得先要文件再补要求）：

```text
在提供范围线文件前，请先确认以下几点（脚本只能粗检，无法自动纠正）：
1. 与总图同一坐标系、同一原点：不要平移、旋转、缩放，另存时不要改插入基点；
2. 图纸单位一致：总图是 mm 就用 mm，总图是 m 就用 m；
3. 范围线须为闭合多段线，最好单独放在一个图层（如 SCOPE-范围线），
   不要混入图框、道路红线、轴线等其它线；
4. 格式：DXF 最稳；DWG 需本机有 CAD（脚本只读打开、读完立即关闭、不保存原文件）。
若第 1、2 条无法满足，请先在 CAD 里把范围线对齐到总图原位（INSERT/ALIGN），
另存 DXF 后再提供；实在无法对齐，可改用「无规划范围」口径（--scope none）。
```

5. 用户给了文件 → `--scope-file`。脚本会做两项粗检：`$INSUNITS` 与包围盒重叠。单位不一致会中断并让你确认（确认已对齐可加 `--scope-file-units assume-drawing`）；包围盒完全不相交会中断，要求用户对齐后重跑。
6. 用户给不出或对不齐 → `--scope none`：统计全部可见图层的填充，总面积取填充合计，**不再做裁剪、范围相交判定、差额校验与道路反算**，交付时必须声明该口径。
7. **裁剪通道必须由用户选（A/B）**：CAD 直连时填充常常只有面积、没有边界，无法判断在不在范围内。脚本会输出 `clip_strict_strategy` 确认项，把两种方式原样告诉用户：**A 导出 DXF 严格裁剪——正确性高、只统计范围内内容、大图可能慢几分钟，适合精确计算；B 保持直连——快，但范围外和跨界填充可能被整块计入，准确性较差、还会多次回问，适合粗略估算**。用户选定前不得继续；选 A 后统计在 DXF 副本上做，写回落到 `_annotated.dxf`；导出失败要给 `clip_export_failed` 确认项，不得静默降级。

### 阶段 2：先看识别对象，再定映射

1. **判断图纸靠什么表达用地**：默认口径就是「只算填充」（`--primitive hatch`），多段线不补缺；整图没有任何填充时才用 `--primitive auto` 整体回退。
2. **用户有明确偏好时**才指定 `--primitive polyline`（只要多段线）或 `--primitive both`（两者去重），以及 `--allow-polyline-fill`（允许用多段线补缺，慎用）。
3. **再看图层**：拿 `--list-layers` 的输出对照 `references/layer-naming-and-mapping.md`：
   - 图层名含用地性质关键词（居住、商业、绿地、道路……）→ 默认映射大概率能命中，直接跑。
   - 图层名是纯编号（如 `A-01`、`LAYER1`）或英文缩写 → 先跑一次，看「待确认图层」清单，再让用户确认对应关系，补 mapping 后重跑。
   - 有图框、轴线、标注图层 → 确认它们在 `ignore_layers` 里，否则会污染重叠检测与统计。

### 单位口径必须先确认

`--unit auto`（默认）时单位来自 `$INSUNITS` 自动判定。`$INSUNITS` 被画图人改错（米制图标成毫米）**不会报错**，面积只会整体差 10⁶ 倍，所以：

- 尺度守卫 `unit_suspect` 只在「按该单位解译整图跨度 <100 m 却有 20+ 图元」这类明显矛盾时拦人；
- 尺度看起来合理的错误标注守卫拦不住，因此未显式给 `--unit` 时一律抛 `balance_params` 确认项（退出码 3），`detail.span_by_unit` 给出同一跨度按 m / mm / cm 解译的对照，让用户对着图判断；
- 显式 `--unit m|mm|cm` 即视为已确认，不再询问；
- 批量/回归可加 `--accept-default-params`，报告记「单位按 $INSUNITS 自动判定、未人工复核」；
- 道路用地反算只在「有规划范围面积 + 覆盖差额 ≤ `--derive-road-tolerance`（默认 1%）」时执行，反算值占范围超 `--derive-road-max-share`（默认 40%）会标需复核，结果与状态写入排查清单；
- 依据可写进 `--params-note`，随报告留痕。

### 确认项最多两轮（batch，实测体验）

脚本默认把「不能猜」的问题**一次汇总**成一份清单（`land_area_confirm.json`，`answer_mode: "batch"`，`count` 为条目数），退出码 3：

| 轮次 | 汇总内容 |
| --- | --- |
| 第一轮（计算前） | 旧标准换算（`standard_conversion`）、未登记代码（图层级，`unregistered_code`）、规划范围（`scope_*`）、单位（`balance_params` / `unit_suspect`）、图层可见性（`layer_state`）、填充裁剪通道（`clip_strict_strategy`） |
| 第二轮（计算后） | 图斑级未登记代码、混合用地未解析（`hybrid_unresolved`）、跨图层重叠闸门（`overlap_gate`） |

会话侧动作固定两步：

1. **一次问完**：把清单里 1..N 项连同各自选项放在同一条回复里问，不要一项一条；
2. **一次重跑**：把用户选中选项里的 `args` 合并成一条命令再执行（例如 `--unit m --accept-default-params --scope-layer "规划范围" --unregistered-code "0905=skip" --overlap-ack`）。

超大图想省掉「先扫再问」的那次扫描时，可加 `--confirm-mode early`：扫描前发现问题立刻中断，代价是问题会分多轮。

### 阶段 3：执行

```bash
# 标准全图测算
python scripts/land_area_report.py --file 总图.dxf --total-area 128.60 --population 32000 --out 平衡表.md

# 需要更细的口径时叠加过滤
python scripts/land_area_report.py --file 总图.dxf --include-codes 07,08,09 --out 平衡表_建设用地.md

# 临时改「建设用地」口径（支持 06-16 区间或 07,08,09 逐项；缺省读分类表 balance_groups）
python scripts/land_area_report.py --file 总图.dxf --construction-codes 06-16 --out 平衡表.md

# 规划范围：用户指定图层 / 提供同坐标系范围线文件 / 确认无范围
python scripts/land_area_report.py --file 总图.dxf --scope-layer "GH-DLK" --out 平衡表.md
python scripts/land_area_report.py --file 总图.dxf --scope-file 范围线.dxf --out 平衡表.md
python scripts/land_area_report.py --file 总图.dxf --scope none --out 平衡表.md

# 直连 CAD 并写回
python scripts/land_area_report.py --source com --write-back --colorize --out 平衡表.md
```

执行后必看三项：终端摘要里的「待确认图层」「异常项」「需复核」。

终端出现 `[重叠]` 时按两类处理，**不要当错误报给用户**。

**第一步：先排除假重叠**（这一步不做，后面的占比判定全部不可信）

出现下列特征时，先怀疑「带洞填充的孤岛被当成实体」，而不是让用户去改图：

- 重叠面积 ≈ 较小地块的整块面积（占比 95%~100%）；
- 大地块的 CAD `.Area` 明显小于各环简单相加（说明它确实带洞）；
- 同一块大地块与多块小地块同时 100% 重叠。

排查动作：① 用 `--cad-areas` 导入 CAD 面积，比对「几何重建 vs CAD」的差值（超过 5% 说明边界离散或孤岛有问题）；② 用句柄在 CAD 里 `HATCHEDIT` 看该填充是否有多个环；③ 确认脚本走的是净几何（`net_geometry`）而不是外环。本技能 v2 起默认用净几何，出现的 100% 重叠应显著减少；若仍大面积出现，按 bug 处理，不得作为「重复描图」交给用户。

- **同图层**：脚本已自动扣减、面积只算一次，**不向用户提问**。交付时看占比（基数=规划范围总面积，`--scope none` 时取分类合计）——
  - ≤1%：交付说明里一句带过，「四、校验 → 同图层重叠」行如实给「N 处 / 扣减 X ha」；
  - **>1%：必须着重提示异常**（不要塞进「需复核」列表一句带过），给出占比与可能原因：① 同一图层内色块重复描画（复制后未删原件）；② 图块展开后与原填充叠加；③ 嵌套包含（整片填充压在细分地块上，如整村宅基地压住各宅基地）；④ 分两次绘制或版本合并导致叠加；⑤ 填充边界自相交/孤岛处理异常。建议按句柄回 CAD 核实并删除重复图元；**面积已按扣减计一次，不影响合计口径，不阻断交付**。
  - 两种情形都固定附一句「如需明细报告加 `--overlap-report`」；用户主动要求才生成 `*_overlap.md`（第一节同图层逐对句柄、第二节跨图层）。
- **跨图层**：两侧面积都保留，按下表判定，不直接当错误报。

判定式：`跨图层重叠面积 ÷ 规划范围总面积`（`--scope none` 时基数取分类合计，并在提示里注明口径）。

| 占比 | 处理 |
| --- | --- |
| ≤ 1%（`--overlap-threshold`，默认 0.01） | 报告「四、校验」一句提示，正常交付，不再追问 |
| > 1% | **停表**，单独成段着重显示并向用户四选一，**未选定前不得交付平衡表** |

超阈值提示话术（数字用实值，禁止省略）：

```text
复检发现跨图层重叠 38 处、共 18.69 ha，占规划范围总面积 596.18 ha 的 3.14%，已超过 1% 阈值。
成因多为同一块地被两层重复描图（例：16 留白用地压在 1401 公园绿地上）。
两侧面积目前都保留在表内，因此 1207 城镇村道路用地的反算值会偏小。
请选择处理方式：
1) 先出土地利用平衡表，暂时不需要明细报告
2) 先出土地利用平衡表，并生成明细的跨图层重叠报告
3) 先不出土地利用平衡表，先仔细检查是否出现其它问题
4) 其它处理方式（按你的说明执行，我会在交付里记明口径）
```

四个选项的执行口径：

- **选 1**：加 `--overlap-ack` 重跑，出表，报告首屏保留醒目提示、「校验」行标需复核，不生成明细；
- **选 2**：加 `--overlap-report` 重跑，出表 + `*_overlap.md`（第一节同图层、第二节跨图层、第三节按图层汇总，末尾附「回 CAD 用句柄定位色块」的 LISP 操作说明）；交付时提醒用户报告末尾有定位方法；
- **选 3**：加 `--diagnose-only` 重跑，只输出排查清单（待确认/未识别图层、未闭合、自相交、填充面积读不到、裁剪与单位口径、道路反算状态），不出表；排查完再回到本判定；
- **选 4**：按用户原话执行，交付说明写明该口径，且不得声称「已校核」。

### 阶段 4：交付与复核

交付话术模板：

> 已完成测算，共扫描 N 个图元，其中 M 个闭合地块参与合计，合计 X.XXXX ha。
> 一级类构成：居住 xx%、公服 xx%、商业 xx%、道路 xx%、绿地 xx%。
> 范围口径：<规划范围图层「X」（1 条 / 多条关系 union）/ 外部范围线文件 X（包围盒重叠 xx%，按同坐标系原位假设对齐） / 无规划范围，总面积为全部可见填充合计，未做差额校验与道路反算>。
> 重叠口径：同图层 K 处已扣减 X ha（占规划范围 Z%，≤1% 或「已超 1%，疑似重复描图/嵌套包含，建议核对句柄」）；跨图层 M 处、Y ha，占规划范围 W%（阈值 1%，已按你选择的方式处理：仅提示 / 已出明细 / 未出表待排查）。
> 需要你确认：`<未识别图层名>`（xx ha）未命中映射，属于什么用地。
> 报告已写入 `<路径>`，含校验、待确认与异常清单。
> 句柄定位：报告里的句柄可直接在 CAD 命令行执行 `(sssetfirst nil (ssadd (handent "句柄")))` 高亮，或 `(command "_.ZOOM" "_O" (handent "句柄") "")` 居中放大；重叠明细报告末尾有完整的定位脚本（含 `GH.lsp` 批量定位），详见 `references/handle-locating.md`。

交付含句柄的成果（重叠明细报告、异常清单、待确认图层示例句柄）时，**一律附上这段定位方法**，不要只丢句柄；报告里的该章节由 `render/markdown_report.py` 的 `_locator_section()` 自动生成，不要手工删除。

## 对话示例

### 示例 1：给了 DXF，要一张平衡表

用户：「这是总图导出的 dxf，帮我算下各类用地面积，出个平衡表，总用地 128.6 公顷。」

执行：

```bash
python scripts/cad_env_check.py --file 总图.dxf --list-layers
python scripts/land_area_report.py --file 总图.dxf --total-area 128.6 --out 平衡表.md
```

期望产出：Markdown 报告**只有一张表**——`## 一、规划土地利用平衡表`（一级/二级/三级 + 建设用地小计 + 总用地面积，只列实际出现的层级），另有规划范围、图层可见性、校验（道路反算后 12 类补齐、合计与 128.6 ha 吻合）、待确认图层、异常清单、测算说明（含一级类地块数与人均）。

混合用地在表里**单独成行**：`070101+0809`（名称 `一类城镇住宅用地+15分钟社区生活圈综合公共服务设施用地`）紧跟 `070101` 之后，面积独立计量再逐级加和；`0807+090101` 则是 08 下的一条二级行。例：`070101:30 + 070102:50 + 070101+0809:50` → `0701:130`、`07:130`。

注意口径：只统计填充，道路（1207 城镇村道路用地）通常不填充，由「范围 − 其他一级类 − 未识别」反算。所以看到「已识别远小于规划范围」**先看校验表的「道路反算」行**：显示反算公式即属正常；显示「已阻断」才是问题，此时应先把待确认图层清零（补 mapping 或 `--exclude-layers`）再重跑，而不是手工把差额塞进 12 类。

期望产出：图纸当前文档的 `AREA_LABEL` 图层出现形如 `0701 3.0000ha` 的标注，各一级类按调色板着色；报告同步生成。交付时必须提醒：**标注已添加到当前图纸但未保存，请确认后自行保存**，并且原始数据未做任何修改（未删改图元）。

## 复核要点清单

- 单位是否交代清楚，是否可能是毫米图被当成米（按当前单位解释后「整图跨度 <100 m 却有 20 个以上图元」必须已触发 `unit_suspect` 并问清）；
- 规划范围面积是否取自 CAD 自算 `.Area`（报告「面积来源」行）、几何离散与它的偏差是多少（>0.1% 必须进校验）；范围线含圆弧时尤其要看这一行；
- 规划范围是自动识别还是用户指定？用户是否否认过自动判断的图层？
- 用外部范围线文件时：`$INSUNITS` 是否一致、包围盒重叠比是多少、报告是否写明「未做坐标纠偏」；
- 用 `--scope none` 时：是否写明总面积取填充合计、未做差额校验与道路反算；
- 「规划范围 − 已识别」的差额是否已由道路反算解释（而非未识别面积伪装成道路）；
- 反算得到的 12 类占比是否明显离谱（>40% 会有需复核提示），是否疑似整类用地没填充；
- 待确认图层是否已清空或已向用户确认；
- 未闭合、自相交是否逐条给出句柄，且交付时是否附上「回 CAD 用句柄定位图元」的方法（`handent` / `ZOOM Object` / `GH.lsp`，见 `references/handle-locating.md`）；
- 同图层重叠是否已扣减（同一图层不得重复计面积）、校验行是否带「如需明细报告加 --overlap-report」、全程是否为同图层重叠追问用户（应为否）；
- 同图层扣减占规划范围 > 1% 时，是否已在交付说明中着重提示异常并列出可能原因（重复描图 / 块叠加 / 嵌套包含 / 分次合并 / 自相交）；
- 跨图层重叠占规划范围 > 1% 时，是否已停表并让用户四选一（未选定不得交付）；明细是否只在用户选 2 时生成；
- 含圆弧的地块面积是否明显偏离手算值；边界是否走 ezdxf 官方 `from_hatch`+`flattening`（自写弧段会画到反侧，导致外环自交、面积虚大）；
- 带孤岛的填充是否按净面积统计（外环减洞），是否**同时**用净几何做重叠/裁剪；出现 95%~100% 重叠时是否已按「假重叠」排查，而不是让用户改图；
- 是否导入过 CAD 自算面积（`--cad-areas`）：报告是否注明「面积来源：CAD 自算 N 个 / 几何重建 M 个」，差额超过 5% 的是否进了异常清单；
- 是否出现 `hatch_area_unavailable`（说明兜底未生效）；
- 同一块地是否被填充与多段线重复统计（看说明里的去重条数）；
- 占比基数用的是规划范围还是分类合计，是否在报告里写明。

## 常见误用

| 误用 | 后果 | 正确做法 |
| --- | --- | --- |
| 把未识别图层面积摊进其他类目 | 平衡表失真 | 保留待确认清单，让用户确认性质 |
| 重叠图元直接按告警数扣减 | 少算面积 | 只告警，交由用户判断是否重复 |
| 填充与多段线同时统计 | 面积翻倍 | 用默认 `--primitive hatch`（只算填充）；确需合并时才用 `--primitive both` 并按填充优先去重 |
| 用外环面积代替带洞填充的净面积 | 面积偏大 | 交给脚本按奇偶嵌套算净面积，不要手工取外环 |
| 填充 Area 读不到就跳过该地块 | 漏算 | 保持兜底开启，导出 DXF 重建边界 |
| 未闭合边界强行闭合 | 面积偏小且难以发现 | 列入异常清单，请设计方闭合 |
| 缺 `--total-area` 却说「覆盖率 100%」 | 结论无依据 | 明确说明未提供规划范围总面积，跳过覆盖率校验 |
| 拿图框或道路红线当规划范围 | 面积被裁小或整体错位 | 让用户确认范围图层；不确定就用 `--scope-file` 或 `--scope none` |
| 识别不到范围就按全图算且不告知 | 结论被当成已校核 | 交出 `scope_not_found` 确认项，问清「图层名 / 文件 / 无范围」三选一 |
| 拿到 DWG 范围线直接用，不提前提醒 | 坐标系或单位不一致，面积整体失真 | 先原样发出 4 条前置要求，再用 `--scope-file` 粗检 |

## 执行细节（范围识别与裁剪口径，原 SKILL.md 核心工作流）

1. **确认数据源**：按「运行中的 CAD → 本机已安装的 CAD（自动启动）→ DXF 文件」三级顺序取数。用户在 CAD 里开着图纸就走 COM；没开但装了 CAD，脚本会自动启动（不想启动就加 `--no-start-cad`）；本机没有 CAD 才要求提供 DXF。只给 DWG 时先让其另存 DXF，不要尝试直接解析 DWG。
2. **确认识别对象**：图纸一般用**色块填充（HATCH）**表达用地性质，而多段线常不闭合。默认 `--primitive hatch`，**只算填充**、多段线不补缺；只有整图一个填充都没有时才用 `--primitive auto` 整体回退多段线。用户明确只有多段线时再加 `--primitive polyline`。
3. **确认规划范围**（必经步骤，不得静默降级，分两步，绝不为找范围线去扫全图图元）：
   - **第一步 只认图层名 + 数线**：跑 `--list-scope-layers`，它只读图层表（不读几何、不导 DXF，几百个图层也是秒级），按 `规划范围线 / 规划范围 / 用地范围 / 规划界线 / 用地界线 / 总用地 / 红线 / 范围线 / 范围 / GHFW(ghfw) / fwx / fw / range / boundary` 命中得到 `matched_layers`（匹配忽略大小写），并对每个候选图层做一次**选择集计数**，给出 `polylines`（该图层多段线数量）与 `line_layers`（确实有线的图层）；
   - 命中后**必须把图层名和线数量交给用户，让用户指定**哪个是规划范围线（退出码 3，`scope_layer_choice` 确认项），**无论命中几个都不得自动进第二步、不得自己挑**；
   - 命中为零 → 把 `all_layers` 拿给用户指认图层名；用户否认候选图层里有真实范围线时同样请其指定（`--scope-layer` 可以指定不含关键词的图层）；
   - **第二步 只进该图层（用户确认后才做）**：`--scope-layer "<图层名>" --list-scope`，只在该图层取边界，输出每个候选的闭合情况、面积与 `decision`，按 `decision.next` 走：
     - `continue`（该图层只有 **1 条**闭合多段线）→ **直接进入测算**，不要再追问草稿或空间关系；
     - `ask_draft`（多条）→ **必须先问有没有未删除的草稿**：有草稿只保留面积最大的一条，不是草稿再按空间关系合成；
     - `ask_scope_layer` → 该图层没有闭合线，请用户换图层 / 先闭合边界 / 提供范围线文件；
   - 用户说没有规划范围 → **先转述范围线文件的前置要求（见 `rules-land-area.md`）再索取文件**；用户能给同坐标系原位的 DWG/DXF，就用 `--scope-file` 裁剪；
   - 用户给不出或对不齐 → `--scope none`：统计全部可见图层的填充，总面积取填充合计，**不再做裁剪、范围相交判定、差额校验与道路反算**，并在报告里声明该口径；
   - **多条边界的空间关系**（用户确认非草稿后）：**相离 → 并集**；**A 在 B 内 → 挖空**（统计两环之间的部分）；**相邻（仅共边）或交叉（有面积重叠）→ 视为绘图问题**，按 `scope_relation` 确认项处理（合并为并集 / 只取最大 / 回 CAD 修好重跑）。
4. **确认口径**：分类标准（默认 2023 指南）、规划范围总面积（ha）、人口规模（人）、是否只统计特定图层或范围。这些信息缺失时按默认值执行，并在成果中明确标注缺失项。**裁剪通道必须由用户选**：需要按范围裁剪、而 CAD 直连读不到填充边界时，脚本输出 `clip_strict_strategy` 确认项（退出码 3），原样告知用户——**A 导出 DXF 严格裁剪，正确性高、可能慢，适合精确计算；B 保持直连，速度快但范围外/跨界填充可能被整块计入，准确性较差且会多次回问，适合粗略估算**；用户选定前不得自行默认。
5. **执行测算**：

```bash
# 全图测算（最常用）
python scripts/land_area_report.py --file 总图.dxf --total-area 128.60 --population 32000 --out 平衡表.md

# 直连活动 AutoCAD 并回写面积标注
python scripts/land_area_report.py --source com --write-back

# 只统计指定范围 / 指定对象 / 指定图层
python scripts/land_area_report.py --file 总图.dxf --scope window --window "0,0,500,600"
python scripts/land_area_report.py --file 总图.dxf --scope handles --handles "1A2B,1A2C"
python scripts/land_area_report.py --file 总图.dxf --layers "YD-居住用地,YD-商业用地"

# 旧国标口径
python scripts/land_area_report.py --file 总图.dxf --standard gb50137

# 规划范围：指定图层 / 外部范围线文件 / 确认无范围
python scripts/land_area_report.py --file 总图.dxf --scope-layer "GH-DLK"
python scripts/land_area_report.py --file 总图.dxf --scope-file 范围线.dxf
python scripts/land_area_report.py --file 总图.dxf --scope none

# 严格裁剪（直连读不到填充边界时，先导 DXF 再按范围裁剪）
python scripts/land_area_report.py --source com --clip-strict on
```

6. **复核并交付**：读取生成的 Markdown，把「校验」「待确认图层」「异常清单」三节当作必读内容向用户汇报，不要只报合计面积。报告 `## 一、规划土地利用平衡表` 节即范式平衡表（一级/二级/三级 + 建设用地小计 + 总用地面积），**报告只出这一张表**（一级类平铺表与二级类明细已取消，地块数与人均改在「测算说明」里给）；建设用地口径来自分类表 `balance_groups.construction`，需要临时改口径用 `--construction-codes`，不要改代码。表里「占建设用地比例」**只对建设用地大类（06–16）填写，非建设用地（01–05、17–24）该列留空**（它们不是建设用地，填了会读错分母），「占总用地比例」照常给值。
