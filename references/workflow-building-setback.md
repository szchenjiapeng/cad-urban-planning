# 子技能 N3：建筑退线

触发词：退线、建筑退线、建筑控制线、退距、后退红线、退让、压线检查、建筑退让。

## 1. 原理

退线 = 把「可建范围」求出来，再画它的边界：

| 基准 | 计算 |
| --- | --- |
| 用地红线 (`--basis parcel`) | `可建 = 地块.buffer(-d)`，`d` 按建筑高度分级：低多层 5m / 高层 10m |
| 道路红线 (`--basis road`) | `可建 = 可建 - 红线.buffer(d)`，`d` 按道路等级：快速 20 / 主干 15 / 次干 10 / 支路 5 |
| 两者 (`--basis both`) | 先按用地内缩，再扣掉临路范围，取交集 |

### 三种口径的差别（**必须先讲给用户听，再让用户选**）

只丢「parcel / road / both」三个词，用户无法判断差别。提问时必须带上这张对照表：

| 口径 | 退的是什么界线 | 反映什么 | 适用场景 | 退距来源 |
| --- | --- | --- | --- | --- |
| `parcel` | 只退用地红线：`可建 = 地块.buffer(-d)` | 地块**自身**的退让，界外是路、绿地还是空地都不影响 | 地块内可建范围、拿地强排、出让条件核算 | 低多层 5m / 高层 10m |
| `road` | 只退道路红线：扣掉沿红线的 `d` 带 | **临路界面**退让，同一条路两侧地块退距一致 | 道路两侧界面与街墙控制、沿街退线研究 | 快速 20 / 主干 15 / 次干 10 / 支路 5 |
| `both` | 先按用地内缩，再扣临路带，取交集 | 同时满足自身退让与临路退让（最严） | 出具正式**建筑控制线**成果、报建审查 | 取两者较大 |

落地要求：

- `--basis` 不填时脚本输出 `setback_basis` 确认项（退出码 3），`detail` 里带 `basis_options`（三种口径的完整解释）、本图识别到的用地图层/道路红线图层、道路等级判定与当前退距规则，让用户看着本图数据选；
- `--confirm-layers` 的输出里也带 `basis_options` 与 `basis_note`，禁止只给词不给解释；
- 本图没有道路红线图层时，`road` / `both` 不可用，要明确告诉用户「只能选 parcel 或补图层」。

**出线口径**：低多层控制线（5m）与高层控制线（10m）各写一个图层；地块能判定高度时只出对应那一条，判定不出时两条都出（见第 3 节）。压线检查按该地块实际采用的控制线执行。

### 六项口径必须先确认（硬性）

除退距数值与退线基准外，下面六项同样会实质改变成果，未逐项指定时脚本抛 `setback_options` 确认项（退出码 3），`detail.items` 每项带 `question` / `evidence` / `recommended` / `flag`：

| 口径 | 为什么必须问 | 对应 flag |
| --- | --- | --- |
| 建筑图层 | 图上有「选取现状建筑」这类空图层陷阱，选错会得 0 栋或重复计入；塔楼/裙房常分层 | `--building-layers` |
| 绿地水系地块 | 绿地、水域不设建筑退线，留不留决定成果地块数 | `--green-parcels include\|exclude` |
| 高度分级 | 抓得到高度只出一条线，抓不到两条都出，压线清单差别大 | `--height-class` / `--high-rise-layers` / `--no-height-text` |
| 杂线阈值 | 决定哪些碎线被删、可建面积大小 | `--min-ring-width` / `--min-ring-area` |
| 环清理策略 | 内院（洞）留不留、同层重线怎么去、共线重叠怎么处理 | `--keep-holes` / `--ring-dedupe` / `--coincident-policy` |
| 规划范围 | 不裁剪会把范围外地块一起算，数量与压线清单全变 | `--scope-mode` / `--scope-layers` |

一次性接受建议值用 `--accept-default-options`，报告「一、测算口径 → 口径确认」会写「按推荐值执行」并列出每项实际取值；JSON 落在 `options.resolved`。

### 退距规则来源必须先问（硬性）

`assets/setback_rules.json` 的 `_status` 为「内置通用默认值（未按地方标准校准，可按院内标准替换）」，**退距直接决定建筑控制线位置**，各城市差异很大（低多层常见 3~6m、高层 8~15m），照搬默认值出成果等于拿默认值当标准。

| 情形 | 脚本行为 |
| --- | --- |
| 用默认规则文件 + `_status` 非空 + 未加 `--accept-default-rules` + 未给 `--distance-override` | 输出 `setback_rules_source` 确认项（退出码 3），`detail.values` 列出低多层/高层/临绿地水系/道路四级当前取值 |
| 用户同意按内置默认值 | 加 `--accept-default-rules`；JSON `rules_source.source = 按内置默认值（用户已确认）`，报告头部写明「未经院内标准校准，不得直接作为报建依据」 |
| 用户提供数值 | `--distance-override "低多层=6,高层=12,临绿地=5,主干路=18"`，来源记为「命令行覆盖（用户提供）」 |
| 用院内/地方标准 | `--rules 标准.json`（结构同默认文件），来源记为「院内/地方标准文件」，报告写文件路径 |

另外要用 `--rules-note "XX市城市规划管理技术规定 表4.2"` 把依据写进报告与 JSON。

**易误读点**：规则文件 `rules` 数组里还有按用地性质的条目（如「商业 3m」），但当前口径走 `parcel_height_rules`（按建筑高度分低多层/高层取距），**这些按用地性质的条目并不生效**，提问与交付时要说清楚，避免用户以为商业地块退 3m。

## 2. 线条图层必须先确认（硬性）

用地色块有字段映射表可依，**线条类图层没有**：规划范围线、用地红线、地块线、道路红线、道路中心线全靠命名，而各院命名习惯差异极大。因此：

1. 脚本只输出**候选与打分**（`--confirm-layers`，退出码 3），不自动采纳；
2. 用户确认后用 `--layer-map layer-map.json` 复用，同图不必重复确认；
3. 同分冲突（如裸 `红线`、`HX`）必须由人指定归属，脚本不猜。

### 命名候选覆盖范围

| 角色 | 典型命名 |
| --- | --- |
| 规划范围线 | 规划范围线、用地范围、总用地、规划界线、GHFW、FWX、BOUNDARY |
| 用地红线 | 用地红线、地块红线、用地界、净用地、用地边界、YDX、DKX、DKHX、HX、用地线、地块线、PARCEL LINE、PROPERTY LINE、REDLINE |
| 地块线（细分） | 用地界线、用地细分、地块分割线、细分线、宗地线、SUBDIVISION |
| 道路红线 | 道路红线、道路边线、路缘线、DLHX、DL-HX、RDHX、RDX、RD-红线、RD-道路红线、ROW、ROAD REDLINE |
| 道路中心线 | 道路中心线、道路中线、中线、RD-ZXX、RD-ZX、ZXX、CENTERLINE、CL |

归一化规则：大小写不敏感、全角转半角、分隔符 `- _ . 空格` 统一、去括号尾注，因此 `RD-道路红线`、`rd-道路红线`、`DL_HX` 视为同类。

## 3. 建筑高度判定与出线口径

判定单位是**地块**，不是单栋建筑：取该地块内最高建筑，决定这块地出哪条线。

### 先确认高度标注图层（推荐必做）

高度/层数文字通常单独放在 `BZ-建筑高度`、`建筑层数`、`标高`、`现状标注` 这类图层，而**线条/文字图层都没有字段映射表**，所以：

1. 先跑 `--confirm-layers`，输出里除线条图层候选外还有 `height_candidates`（按命名打分排序）；
2. 选定后写进 `layer-map.json` 或用 `--height-layers "BZ-建筑高度,建筑层数"` 显式指定；
3. 指定后工具**只扫这些图层**，速度与准确性都最好。

**未指定高度图层时工具会扫描全图文字**：DXF 通道一般可接受，COM 直连大图可能从几秒涨到几分钟；若高度标注分散在多个图层，还会漏抓。遇到慢或抓不全，优先补 `--height-layers`（多图层用逗号分隔）。

| 情形 | 输出 |
| --- | --- |
| 抓到高度/层数，地块内最高 > 24m | 只出**高层**线（10m） |
| 抓到高度/层数，地块内最高 ≤ 24m | 只出**低多层**线（5m） |
| 图纸里没有任何高度/层数信息 | **两条线都出**（低多层 + 高层，供对照） |

### 高度抓取顺序

| 顺序 | 写法示例 | 结果 |
| --- | --- | --- |
| 1 高度文本 | `54m`、`54.0米`、`H=54`、`高度:54` | 54m |
| 2 楼层 | `5F`、`7F`、`6层` | 楼层 × 3m（7F → 21m） |
| 3 结构前缀 + 层数 | `砼7`、`砼15`、`砖6`、`砖混5`、`框4`、`钢3`、`木2` | 楼层 × 3m（砼15 → 45m） |
| 4 图层名 | `JZ-18F`、`现状-砼6` | 同上 |
| 5 纯数字 | `54.00` | **不采集**（避免标高/面积/编号误判） |
| 6 都没有 | — | 两条线都出 |

约束：

- 高度文字必须落在建筑轮廓内（外扩 0.5m 容差），图例、指标表、说明文字不计入；
- 同一栋建筑多行文字取最大值；同一地块取地块内最高建筑（按建筑代表点归属地块，避免串算）；
- `--high-rise-layers` / `--low-rise-layers` 人工指定优先于自动抓取；
- `--height-class low_mid|high` 可强制所有地块只出某一条线（`auto` 为默认）。

阈值与换算可配：`high_rise.max_height`（默认 24m）、`--floor-height`（默认 3m/层）。

## 4. 临绿地水系退 5m

用地红线一侧**只要直接相邻**绿地或水系，该边段退距为 **5m，与建筑高度无关**（高层也退 5m）：

| 项 | 口径 |
| --- | --- |
| 适用大类 | `01 耕地`、`02 园地`、`03 林地`、`04 草地`、`14 绿地与开敞空间用地`（含 1401 公园绿地、1402 防护绿地、1403 广场用地）、`17 陆地水域` |
| 宽度判断 | **不做**：绿地水系再窄也退 5m |
| 相邻判定 | 必须直接相邻（间距 ≤ 0.1m），隔路、隔其他用地不算 |
| 接触长度 | ≥ 2m（防止角点相接就放宽整侧），可配 `--min-contact-length` |
| 界外未绘制 | 无法判定 → 按高度规则，报告注明 |

实现方式是「整块按高度退，再把临绿地边段多退的那一圈还回来」，5m 与 10m 交界处自然形成台阶。

## 5. 道路等级：宽度不参与判定

**红线宽度与道路等级没有必然对应关系**，主干路以下尤其如此：存在比主干路更宽的次干路。所以：

| 优先级 | 来源 | 是否自动采纳 |
| --- | --- | --- |
| 1 | `--road-levels "RD-解放路=主干路"` | 是 |
| 2 | 图层名关键词（主干/GR/ZJ/快速路、次干/CG、支路/ZL/街坊路） | 是，报告列出 |
| 3 | 实测红线宽度 | **否**，只进报告「宽度参考」列 |
| 4 | 都没有 | 按默认退距 + 报告标注；`--level-policy ask` 可改为强制确认 |

## 6. 命令

```bash
# 1 先看线条图层候选（不产成果，退出码 3）
python scripts/up.py setback --file 总图.dxf --confirm-layers

# 2 确认后写入指派表并复算（默认已含两级退线 + 临绿地 5m，默认出 DWG 副本）
python scripts/up.py setback --file 总图.dxf --basis both \
  --layer-map layer-map.json --out 退线成果.md

# 3 显式指定建筑分级与道路等级（最可靠）
python scripts/up.py setback --file 总图.dxf --basis both \
  --high-rise-layers "JZ-高层,JZ-超高层" \
  --road-levels "RD-解放路=主干路,DL-纬三路=次干路" \
  --out 退线成果.md

# 4 覆盖退距（如院内标准不同）
python scripts/up.py setback --file 总图.dxf --basis both \
  --distance-override "低多层=6,高层=12,临绿地=5,主干路=18"
```

## 7. 参数

| 参数 | 说明 |
| --- | --- |
| `--basis parcel\|road\|both` | 退线基准；**不填则输出 `setback_basis` 确认项**（退出码 3），先解释三种口径再选 |
| `--scope-mode none\|auto` | 规划范围裁剪：`none` 不裁剪（默认，兼容旧口径）；`auto` 只算规划范围内地块与建筑，范围外进「剔除统计」 |
| `--scope-layers` | 规划范围图层，逗号分隔；缺省按「规划范围/设计范围」命名识别（配合 `--scope-mode auto`） |
| `--confirm-layers` | 输出线条图层候选与打分（退出码 3） |
| `--layer-map` | 图层指派表 JSON，确认结果复用 |
| `--building-layers` / `--parcel-layers` / `--road-layers` | 显式指定图层，优先级最高 |
| `--rules` | 规则文件，默认 `assets/setback_rules.json`（院内/地方标准请指定本参数） |
| `--accept-default-rules` | 明确同意按内置默认值退距执行；不加且规则仍为默认值时输出 `setback_rules_source` 确认项 |
| `--rules-note` | 退距依据说明（如规范条文号），写入报告与 JSON |
| `--default-distance` | 规则未命中的退距 |
| `--distance-override` | `"低多层=6,高层=12,临绿地=5,主干路=15"` |
| `--road-levels` | `"图层名=等级"`，等级未判定时用它兜底 |
| `--level-policy default\|ask` | 等级未判定时：按默认退距 / 输出确认项 |
| `--high-rise-layers` / `--low-rise-layers` | 建筑分级图层 |
| `--height-class auto\|low_mid\|high` | auto=按图纸高度自动判定，抓不到则两条线都出；low_mid/high=强制只出该条线 |
| `--floor-height` | 楼层换算高度，默认 3m/层（砼15 → 45m） |
| `--height-tolerance` | 高度文字归属建筑的容差，默认 0.5m |
| `--height-layers` | 只扫指定图层的高度/层数文字（推荐，显著提速；多图层逗号分隔） |
| `--no-height-text` | 不扫文字，仅用图层名与 `--high-rise-layers` 判定高度 |
| `--green-landuse` | 视作绿地水系的一级类，默认 `01,02,03,04,14,17` |
| `--min-contact-length` / `--side-tolerance` | 相邻判定的接触长度与容差 |
| `--out-layer-low` / `--out-layer-high` | 两级退线图层名 |
| `--offset-join mitre\|round\|bevel` / `--mitre-limit` | 锐角处理 |
| `--min-building-area` | 建筑最小基底面积，默认 10 ㎡ |
| `--tolerance` | 压线判定容差（占基底比例），默认 0.01 |
| `--min-ring-width` | 退线环最小短边宽度（m），低于判杂线不写图，默认 5 |
| `--min-ring-area` | 退线环最小面积（㎡），低于判杂线，默认 10 |
| `--keep-holes` / `--keep-hole-area` | 可建范围内部的内环（洞）：`large` 默认（≥100㎡ 视为真实内院保留）/ `all` / `none` |
| `--ring-dedupe on\|off` | **同一输出图层内**重线去重（完全重合 / 被覆盖），默认 on；跨图层一律不去重 |
| `--coincident-policy report\|merge\|ignore` | 同图层部分共线重叠边段：`report` 只列清单不删线（默认）/ `merge` 合并成一条外轮廓（失去分地块属性）/ `ignore` |
| `--green-parcels include\|exclude` | 绿地水系地块是否参与退线；不填则进 `setback_options` 确认项 |
| `--accept-default-options` | 一次性接受口径建议值（建筑图层仍按识别结果），报告记「按推荐值执行」 |

## 8. 校验

| 校验 | 说明 |
| --- | --- |
| 建筑压退线 | 建筑与所属等级退线带相交超过容差 → 冲突清单，给建筑句柄 + 所属地块 + 分级 |
| 内缩退化 | 退距大于地块宽度 → 面积 ≤ 0，列异常，不画 |
| 地块未临路 | 明确写「地块未与任何红线相交」，不静默按 0 处理 |
| 红线缝不成面 | 列异常并提示先闭合红线 |
| 等级未判定 | 报告中标注「按默认退距」，不冒用某一等级的数值 |
| 绿地为邻但未绘制 | 报告注明「界外邻接用地未绘制，未适用绿地水系特例」 |
| 图形核查 | 写出的每条环必须闭合；无效环（自交/顶点不足）、内环碎线、面积 <10㎡ 或最小短边宽 <5m 的杂线、**同图层**重线，全部删除并逐条留痕（报告第八节） |
| 规则来源 | 规则文件仍为默认值且用户未确认 → 不计算，先抛 `setback_rules_source`；报告必须写明退距依据来源（内置默认值已确认 / 用户数值 / 院内文件） |

## 9. 成果

- **默认出 DWG 新副本** `<原名>_退线.dwg`（AutoCAD 2018 格式），原图不动；本机无法执行 CAD 时回退 `<原名>_退线.dxf`，并在报告与 JSON（`copy_note`）写明原因；
- `--copy-out 成果.dwg` 可改路径/格式（扩展名优先）；`--no-write-back` 只出报告不导图；
- 两条退线分别写入 `KZX-退线-低多层`、`KZX-退线-高层`，**全部为闭合多段线**（DXF `close=True` / COM `Closed=True`）；
- 报告含：退线计算结果（基准/等级或高度/退距/依据）、两级可建范围面积与退让比例、临绿地水系边段表、道路等级判定表（含宽度参考）、异常与压线清单、**图形核查与清理**（输入环数/写出环数/删除环数/删除面积、逐条删除明细、同层共线重叠清单）。

### 术语：什么算「重线」

| 情形 | 判定 | 处理 |
| --- | --- | --- |
| 同一输出图层内，两环几何完全重合 | 重线 | 删重，保留一条 |
| 同一输出图层内，一环被另一环覆盖（IoU ≥ 0.99 或覆盖率 ≥ 0.99） | 重线 | 删小留大 |
| 同一输出图层内，两环有部分共线重叠边段 | 疑似重线 | 默认只进清单不删线（删了破坏闭合）；`--coincident-policy merge` 才合并 |
| **低多层线 与 高层线** 之间重合（如临绿地水系两侧同为 5m） | **不是重线** | 不处理，报告注明属规则结果 |
| 父地块与子地块的嵌套环（一大一小、互不重合） | 不是重线 | 保留 |

### 内部碎细线从哪来

`shapes.to_rings()` 会把**外环 + 全部内环（洞）**都吐出来，`shrink_except` 的「还回带」求差后还会留下窄条碎片。清理只发生在写图环节（`lib/ring_clean.py`），不改变面积口径：`setback.json` 里 `buildable_*` 仍是几何面积，另给 `rings.*.written/dropped` 与逐条明细，禁止静默删。

## 10. 常见坑

- 用**已经内缩后的可建范围**判断是否临路，会把临路地块误判成不临路（代码已固定用原始地块判断）；
- 临绿地水系判定用的是**原始地块边界**，不能用内缩后的范围，否则接触关系丢失；
- 图纸单位是毫米时退距要换算，脚本按 `$INSUNITS` 自动处理，报告写明单位依据；
- 建筑图层里混了家具/轴线/图例 → 先看 `--min-building-area` 与图层名，必要时用 `--building-layers` 精确指定；
- 裸「红线」「HX」图层不要强行自动归类，必须让用户指定是道路红线还是用地红线。
