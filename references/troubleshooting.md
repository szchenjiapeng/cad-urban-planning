# 常见问题排查

## 1. 连不上 CAD / 提示 COM 不可用

脚本按三级顺序取数：**运行中的 CAD → 启动本机已安装的 CAD → DXF 文件**。先跑自检确认卡在哪一级：

```bash
python scripts/cad_env_check.py
```

| 自检结果 | 含义与处理 |
| --- | --- |
| `com: true` | 已连上活动图纸，可直接跑 |
| `cad_installed: true`、`com: false` | 装了但没运行，运行时会自动启动（首次 10–30 秒）；不想弹窗用 `--no-start-cad` |
| `cad_installed: false` | 本机无 CAD，必须 `--file` 指定 DXF |
| `pywin32: false` | 缺依赖，`python -m pip install pywin32` |

其他排查：

1. AutoCAD 必须已**打开图纸**，COM 只能读活动文档；空文档会提示"没有可用的图纸"。
2. AutoCAD LT 不提供完整 ActiveX 自动化接口，只能走 DXF。
3. 权限不一致（管理员启动的 CAD + 普通权限脚本）会导致 COM 互相不可见，保持同一权限会话。
4. 中望 CAD、浩辰 CAD 等提供 COM 兼容接口，把 ProgID 换成对应产品的值：`--progid` 或环境变量 `CAD_PROGID`。
5. 自动启动被组策略/安全软件拦截时，先手动打开 CAD 再运行。

## 2. 填充（HATCH）读不出面积：报"输入无效"、GetLoopAt 返回空

这是图形本身或接口的常见问题，不是面积真的为 0。处理链路是脚本内建的：

1. COM 读 `Hatch.Area` 失败 → 记下句柄，不跳过；
2. 把这些对象复制到新文档并导出临时 DXF（不改动用户当前图纸）；
3. 用 ezdxf 解析边界（支持多段线边界、直线/圆弧/椭圆/样条边），逐环重建多边形；
4. 按**奇偶嵌套规则**算净面积：深度 1 计入、深度 2（孤岛）扣除、深度 3 再加回。

报告「测算说明」会写明重建了多少个填充。若仍出现 `hatch_area_unavailable`：

- 确认没有加 `--no-hatch-fallback`；
- 在 CAD 里对该填充执行 `HATCHEDIT` 重新指定边界，或 `REGEN` 后重试；
- 填充边界是样条且严重退化时，可先用 `EXPLODE` 炸开后重新 `HATCH`。

## 3. 只有 DWG 文件

`ezdxf` 不能直接读 DWG。两条路：

- 在 CAD 里另存为 DXF（最省事）；
- 用 ODA File Converter（免费）批量转换：`ODAFileConverter.exe <输入目录> <输出目录> ACAD2018 DXF 0 1 "*.dwg"`。

脚本检测到 `.dwg` 会直接报错并给出这条指引，不会静默失败。

## 4. 面积明显偏大或偏小

- 检查图纸单位判定。报告头部的 `unit` 与 `unit_source` 说明是来自 `$INSUNITS` 还是启发式推断。
- 总图常见单位是毫米，1 m² = 1e6 mm²；结果大了 10⁶ 倍就是单位问题，用 `--unit mm` 强制指定。
- 图形被 `SCALE` 过但没改单位时无法自动识别，需要参照已知长度人工换算。

## 5. 大量多段线被列为"未闭合"

- 图元确实开口：请设计方闭合，或用 `--closure-tolerance` 放宽首尾点距离阈值（单位同图纸单位）。
- 由直线/圆弧拼成的边界不是多段线：脚本只能识别多段线/填充，建议改按填充识别（默认策略即可），或 `PEDIT` → `JOIN` 合成闭合多段线。
- 图元在外部参照（XREF）里：外部参照内容不在当前图形数据库内，需绑定后再算。

## 6. 填充与多段线都算了一遍，面积翻倍

- 默认 `--primitive hatch` 只统计填充，多段线全部不计入（报告说明里写明丢弃条数）；确需两者合并才用 `--primitive both`，并按填充优先去重。
- 若确认仍有重复，检查是否用了 `--primitive both` 且填充缺几何（此时无法判重）；
- 也可能是两块地本来就重叠，看「异常清单」的 overlap 告警并用句柄定位。

## 7. 带洞的填充面积偏大

- 说明脚本只识别到了外环。检查「异常清单」与「测算说明」是否提示边界解析失败；
- 若填充的洞是通过"孤岛检测"自动生成的（未真正绘制边界），DXF 里可能没有孤岛路径，需要在 CAD 中显式绘制洞口边界后重新填充。

## 7.1 重叠 95%~100%，但 CAD 里是挖空的

- 成因一：面积扣了洞，重叠求交却只取外环 → 洞内小地块被判整块重叠（v2 起统一走净几何 `net_geometry`，不再出现）。
- 成因二：弧段离散把外环画到反侧，外环自交、面积虚大（v2 起优先用 ezdxf `from_hatch` + `flattening`）。
- 排查：先 `--cad-areas` 导入 CAD 面积对账，再看该填充在 CAD 里 `HATCHEDIT` 有几个环；差额超 5% 说明边界仍有问题，按 bug 处理，不要让用户改图。

## 8. 范围图层里有多条闭合线

- 1 条：`decision.next=continue`，直接测算，不要再问。
- 多条：脚本先出 `scope_draft_check`，问是否为未删除的草稿。有草稿用 `--scope-outer-only` 只取最大一条；都不是草稿再按空间关系处理——相离取并集、A 在 B 内自动挖空（统计两环之间）、相邻/交叉按绘图问题中断。
- 想跳过询问批量跑：显式给 `--scope-relation union|difference|intersect` 或 `--scope-outer-only`。

## 9. 范围外的面积被算进来了

- 正常口径下范围外一律不计；先看报告「规划范围与裁剪」里 **未能裁剪（bypass）** 的条数。
- bypass > 0 说明有填充读不到边界（CAD 直连常见）。按 `--clip-strict on` 重跑会先导出 DXF 补齐边界；也可以直接在 CAD 里另存 DXF 后用 `--file`。
- 若用了 `--scope none` 或 `--clip whole`，属于显式放宽口径，报告首屏会标注，不能当已校核结果交付。

## 10. 疑似重叠告警

脚本只告警不扣减，因为规划口径里"重叠"可能是立体分层、地下空间或错误复制。**先按 7.1 排除假重叠**（带洞填充、弧段离散），再按下面处理：

- 用报告中句柄在 CAD 里 `SELECT` → 输入句柄定位；
- 确认是重复图元就删除后重跑；是不同口径就保留并在说明中注明。

## 9. 中文乱码 / UnicodeEncodeError

Windows PowerShell 默认编码不是 UTF-8。脚本已内置 `sys.stdout.reconfigure(encoding="utf-8")`，若终端仍乱码，先执行：

```powershell
chcp 65001
$OutputEncoding = [Console]::OutputEncoding = [Text.UTF8Encoding]::new()
```

文件输出统一 UTF-8（无 BOM）。

## 10. 缺少依赖

```powershell
python -m pip install ezdxf
# COM 通道（仅 Windows，可选）
python -m pip install pywin32
# 建筑退线 / 城市控制线（必需，缺了会以退出码 5 中断）
python -m pip install shapely
```

脚本不会自动安装依赖。缺 `ezdxf` 时无法运行任何通道；缺 `pywin32` 时只影响 COM；
缺 `shapely` 时平衡表只能粗算裁剪，而**退线与控制线直接报错退出，不做近似降级**。

## 11. 平衡表专项排查（原 SKILL.md 失败处理）

- 连不上 AutoCAD：确认已打开图纸、非 AutoCAD LT，或改 `--file` 走 DXF；其余排查见本文档前文。
- CAD 未运行：脚本会按需自动启动本机已安装的 CAD，首次启动可能需要 10–30 秒；不想启动就加 `--no-start-cad`。
- 命令「卡住」很久（COM 通道）：默认 `--blocks expand` 会先把整图导出 DXF，4 万图元以上还要逐图元读属性，属于分钟级耗时。先看终端有没有 `[扫描] 多段线 1500/43000` 这类进度；日志停住不动就是异常，按退出码 4 的提示排查：关掉 CAD 的模态对话框 → 加 `--blocks skip` → 或另存 DXF 用 `--file`（后续重跑秒级，块展开的 DXF 也会按图纸 mtime 缓存复用）。`--list-scope` 已自动只扫范围相关图层并跳过块展开，不要为了它再加 `--blocks expand`。
- 填充面积读不到（`hatch_area_unavailable`）：确认没有加 `--no-hatch-fallback`；兜底会导出 DXF 重建边界，仍失败说明填充本身损坏，需要 `HATCHEDIT` 重画或 `REGEN` 后重试。
- 裁剪出现「未能裁剪（bypass > 0）」：说明有填充只读到面积、没有边界，无法判断在不在范围内。用 `--clip-strict on` 重跑（先导出 DXF 补齐边界），或在 CAD 里另存 DXF 后用 `--file`；**bypass > 0 的结果不得当作已校核交付**。
- 面积比 CAD 里量的大（`area_mismatch` 较多）：DXF 的弧边要重新离散，`ccw` 标反时会被放大成倍。脚本对含弧填充做两套离散比对，取与 CAD 自算面积吻合（<5%）且包围盒正常的一套；仍对不上的一律按 CAD `.Area` 计面积，几何只用于裁剪，报告「弧段还原」校验行会给出块数。
- 终端抛「被呼叫方拒绝接收呼叫」（`RPC_E_CALL_REJECTED`）：CAD 弹了模态对话框或正在执行命令。扫描已对这类错误自动退避重试 4 次；仍失败就关掉对话框再跑，已扫完的部分会走扫描缓存，不会白扫。
- 重跑时想强制重新扫图元：加 `--no-scan-cache`；缓存按「路径 + mtime + size」失效，图纸另存或改动后自动重扫。
- 未登记代码 / 旧标准的追问现在发生在扫描之前（只看图层表），并会自动排除「规划范围内面积为 0」的未登记图层；若在扫描前就看到确认清单，属正常，不必等整图扫完。
- 只有 DWG：在 CAD 中另存 DXF，或用 ODA File Converter 批量转换，不要用 ezdxf 硬读。
- 结果整体放大或缩小 10⁶ 倍：单位问题，用 `--unit mm` 或 `--unit m` 显式指定。
- 大量「待确认图层」：用 `references/layer-naming-and-mapping.md` 的规则调 mapping，重跑后确认清单清空。
- 中文乱码：先 `chcp 65001`，脚本已内置 UTF-8 输出。

## 12. 新增子技能（地块编号 / 退线 / 控制线）排查

- **缺 shapely**：`RuntimeError: 缺少依赖 shapely`，退出码 5。安装后重跑；不要试图让脚本近似降级。
- **地块编号 0 个**：先看报告「五、未识别图层」。常见原因：图层名既无代码也非中文原名；地块不是闭合多段线/填充；范围线被误设成地块（`用地界线` 已被排除）。
- **编号重复或顺序不对**：检查是否同一块地被两层重复描图；排序规则 `--sort row` 依赖质心坐标，跨图幅拼接的图纸要先确认坐标系一致。
- **未登记代码一直挡着**：`0905` 这类图层名会要求确认。要么改图层名，要么用 `--unregistered-code "0905=map:0902"`，要么先跑 `add_classification_node.py` 登记新代码。
- **退线没有结果**：多为退距大于地块宽度导致内缩退化，报告「异常清单 → offset_failed」会给句柄；也可能是基准不闭合，先按 `--basis` 换成另一侧基准试。
- **退线画出来了但建筑全压线**：检查 `--tolerance` 与规则表退距是否偏小；若图纸单位是毫米，确认 `$INSUNITS` 正确。
- **控制线某条没生成**：报告里 `状态` 列会写原因。`紫线` 默认 `manual` 属正常；其余多为来源未命中，用 `--line "绿线=code:1401,1402"` 显式指定。
- **控制线互交告警**：红线/绿线在路口、河道处天然重叠，可放宽 `--check-tolerance`；但同一处大面积重叠要回图核对管制范围。
## 13. 建筑量测算与批量建模（N5）排查

- **容积率偏低 / 全是 1 层**：先看报告「无层数建筑」数量。地形图常见「砼」单独出现（已按 1 层）或标注在另一个图层（用 --height-layers 指定）；只有纯数字 6 时默认不采信，确认后加 --bare-number-floors（低置信，报告会标注）。
- **建筑图层识别到了标注层**：BZ-建筑层数 含「建筑」二字，若被当建筑，说明绕开了 label 组排除。统一用 lib/building_massing.resolve_layers，不要自己遍历分组。
- **建筑密度 > 100%**：基底面积合计超过用地面积，多为建筑归属串到相邻地块、或把道路/地块面当成了建筑。先看「建筑清单」的所属地块，再用 --cross-parcel clip 试算对比。
- **建筑栋数比图上少 / 建筑量偏小**：先看报告「重复表达去重」与 `building_duplicate` 清单。同层既有填充又有多段线时，旧口径（`source="auto"` 图层级跳过）会把只用多段线表达的建筑整层丢弃；现统一改为 `both + dedupe`（几何级去重）。若仍偏少，多为填充把几栋楼连成一片（合成一个面），需在 CAD 里拆分填充。
- **建筑量偏大 / 同一栋算两次**：若图纸里填充是「建筑面积色块」、多段线是「建筑轮廓」，两者面积差超 40% 时不会被判重复。先看 `building_duplicate` 是否命中；未命中就说明两条轮廓面积差异过大，需人工确认以哪条为准（可把 `massing_rules.json` 之外的阈值改为传参或在 CAD 里统一表达）。
- **容积率为 0 或极大**：0 说明建筑没归属到任何地块（看 uilding_outside_parcel 异常，多为建筑压在地块边上、代表点落在外侧）；极大说明用地面积取到小块或层数被误读。
- **单图层把地块当建筑**：候选打分应有「与用地地块边界基本重合 → -3」与父面抑制；若仍有大面入选，多为地块没有被识别为用地（--parcel-layers 未给），先用 --confirm-layers 看候选得分与原因。
- **拉伸 0 栋 / EXTRUDE 失败**：看报告「三维拉伸成果」的 需人工闭合 与 不可拉伸 清单。snapped 是原图有缺口（首尾容差吸附），必须在 CAD 里 PEDIT → 闭合 后重跑；自交轮廓要先修形。
- **模型是体块网格不是实体**：当前通道是 DXF，没有 AddExtrudedSolid。要真 3DSOLID 必须 --source com 或本机装 AutoCAD；报告「体块图层（模式 mesh）」会写明。
- **COM 拉伸中途失败**：多为 AutoCAD 弹了模态框。关掉对话框后重跑；单栋失败不影响整批，失败句柄在 extrude.failed 里。
- **砼6 被识别成高度**：不会——层数优先于高度。若文字写成 砼6m 则按高度处理（这是刻意判据，避免把高度当层数），改成 砼6 即可。
