# 图层规范与用地识别

## 1. 定位（硬性）

`assets/layer_spec.json` **只负责三件事**：

1. 图层分组（用地 / 建筑 / 道路 / 控制线 / 标注 / 图框 / 现状）；
2. 新图层命名（`KZX-红线`、`BZ-地块编号` 等）；
3. 排除规则（`用地界线`、`规划范围线`、`图框`、`标注` 不得当地块）。

**用地代码一律委托 `core.classify.LayerMapper` 解析**，禁止在 `layer_spec` 里维护代码表。
否则同一张图会出现「平衡表认 070102、编码脚本认 08」的分歧。

## 2. 用地识别七级优先级

| 级 | 判据 | 示例 | 算地块 | 代码来源 |
| --- | --- | --- | --- | --- |
| 0 | 默认图层 / ignore_layers / 用地组排除词 | `0`、`Defpoints`、`TK-图框`、`标注-01`、`用地界线`、`规划范围线` | 否 | — |
| 1 | 整名就是分类表代码 | `070102`、`0701`、`R2`、`A33` | 是 | 分类表 |
| 2 | 名字含完整分类代码 | `070102-二类城镇住宅用地`、`A33-中小学`、`070102-1` | 是 | 最长代码优先 |
| 3 | 整名就是分类表中文原名 | `二类城镇住宅用地` | 是 | 原名精确匹配 |
| 4 | 混合用地拆段 | `0802+0903`、`070101+0809(30%)` | 是（一块地一个号） | 首段 |
| 5 | 前缀 + 关键词 | `YD-住宅`、`居住用地` | 是 | mapping（低置信） |
| 6 | 形似代码但分类表未登记 | `0905`、`1707` | 是（挂起） | 无 → 必须确认 |
| 7 | 完全不命中 | `MYSTERY_LAYER` | 否 | 进未识别清单 |

## 3. 「是不是地块」与「是什么代码」分开判定

- 是地块 → 照样提取、编号、可做退线基准；
- 代码认不出 → 编号仍生成，但代码列留空 + 进确认/未识别清单；
- 退线、控制线**不需要**地块代码也能跑，不能因为代码认不出就整体中断。

## 4. 新老标准

| 环节 | 2023 指南 | GB 50137-2011 |
| --- | --- | --- |
| 代码形态 | `07` / `0701` / `070102` | `R` / `R2` / `R21` / `A33` / `B1` / `S1` |
| 分类表 | `classification.2023.json` | `classification.gb50137.json` |
| 判标 | `guess_standard()`：成片旧代码优先判 GB50137 | 同左 |

成片出现旧代码时**必须先问用户**：按 GB50137 统计 / 换算成 2023 / 坚持新标准。
新脚本沿用平衡表同一句提问，不自行默认。

注意：`mapping.2023.example.json` 里把 `R1/R2` 映射到 `0701`（兼容做法），
这是既有行为，不要在新脚本里另写一套。

## 5. 纯两位数字的低置信策略

图层名整名只有两位数字（`01`、`07`、`13`、`17`）时：

- **自动地块编号 → 默认排除**（很可能是图号/编号），进未识别清单；
  `--short-code on` 可纳入；
- **显式点名代码 → 允许命中**（如控制线 `code:17` 陆地水域），
  因为用户已经明确要求按该代码取图层。

## 6. 配置结构

```json
{
  "_status": "内置通用默认值（未按地方标准校准，可按院内标准替换）",
  "groups": {
    "landuse": {
      "prefixes": ["YD", "YDD", "GHYD"],
      "aliases": ["用地", "用地性质", "规划用地", "地块"],
      "exclude_keywords": ["规划范围", "范围线", "用地界线", "红线", "退线", "图框", "标注"],
      "range_keywords": ["规划范围线", "用地范围", "用地界线", "GHFW", "FWX"]
    }
  },
  "control_lines": { "红线": {"layer": "KZX-红线", "color": 1, "linetype": "CONTINUOUS"} }
}
```

- `strip_prefixes` / `ignore_layers` / `hybrid_separators` 以 **mapping JSON 为唯一来源**，
  `layer_spec` 不重复配置；
- 颜色为 ACI 索引：红 1 / 黄 2 / 绿 3 / 青 4 / 蓝 5 / 洋红 6 / 灰 8。

## 6.1 建筑组与指标成果图层（N5）

- `groups.building`：`JZ` 前缀 + 「建筑 / 建筑轮廓 / 房屋 / 现状建筑 / 建筑物」别名；
  **必须同时排除 `label` / `frame` / `control` 组**，否则 `BZ-建筑层数` 这类标注图层会被当建筑
  （`lib/building_massing.resolve_layers` 已做该排除，新增子技能不要绕开）；
- 层数/高度标注图层由 `height_layers` 打分给出候选，只用于排序，必须用户确认；
- 成果图层（`assets/massing_rules.json`）：`BZ-容积率`（指标标注）、`JZ-体块`（拉伸体块），
  颜色与模板可替换，不改代码；
- **建筑组为空 = 疑似单图层**：此时不得自动把闭合多段线当建筑，必须走确认项并告知偏差风险；
- 建筑图层里「填充 + 多段线」混合表达很常见：采集统一 `source="both"` + `dedupe=True`
  （`lib/shapes.dedupe_profiles`），不得用 `source="auto"` 的图层级跳过，否则只用多段线画的建筑会整层漏算。

## 7. 院内标准替换清单

拿到院内规范后，按顺序替换：

1. `layer_spec.json` 的 `prefixes` / `aliases` / `control_lines` / `label_layer`；
2. `five_lines.json` 的控制线来源与颜色线型；
3. `setback_rules.json` 的退距、道路等级关键词；
4. 替换后重跑 `python tests/test_new_skills.py` 与平衡表回归。
