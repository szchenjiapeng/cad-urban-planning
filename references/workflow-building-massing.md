# 子技能 N5：建筑量 / 容积率测算与批量建筑建模

触发词：建筑量、建筑面积测算、容积率、FAR、建筑密度、建筑覆盖率、层数、建筑层数提取、建筑轮廓提取、
批量建模、三维拉伸、EXTRUDE、体块、计容、地块指标、建筑量测算表。

一次取数，三个出口，共用同一份建筑清单：

| 出口 | 成果 |
| --- | --- |
| 测算 | `容积率测算表.md` + 新图层 `BZ-容积率`（`编号-用地代码-容积率`）+ DWG 副本 |
| 建模 | `JZ-体块` 图层 + DWG 副本（有 CAD 出 3DSOLID，无 CAD 出体块网格） |
| 数据 | `buildings.json` / `metrics.json`，供退线等子技能复用 |

命令入口三个别名指向同一模块：`up.py massing` / `up.py far` / `up.py extrude`，用 `--task` 区分出口。

## 1. 口径（先说清，再算数）

**这是「简单计容」口径，不是报建口径**，交付时必须原样说明：

- 建筑量 = **基底面积 × 层数**，只含主体建筑；
- 未扣阳台、架空层、设备层、地下车库，也未做规范折算；
- 容积率 = 地块建筑量 ÷ 用地面积；建筑密度（覆盖率）= 基底面积 ÷ 用地面积；
- 层数缺失默认 **1 层**，必须单列清单并提示容积率可能被低估。

## 2. 层数识别

| 写法 | 层数 | 说明 |
| --- | --- | --- |
| `砼6` / `砖混5` / `框架4` | 6 / 5 / 4 | 结构前缀 + 层数 |
| `砼`（后面没有数字） | **1** | 地形图里最常见的写法，单独「砼」即一层 |
| `7F` / `7f` / `7层` | 7 | 层数后缀 |
| `H=54` / `54m` / `54米` | 54 ÷ 层高 | 只有高度时按该地块层高折算 |
| 无任何层数/高度 | **1** | 进「默认 1 层」清单，报告标注低估风险 |
| 纯数字 `6` | 默认不采信 | 避免把标高、编号、面积当层数；`--bare-number-floors` 可开启（低置信） |

冲突处理：同一栋既有 `砼6` 又有 `H=30` 时**以层数为准**（层高由用户指定），
高度折算偏差 > 20% 进异常清单。同栋多个文字取**众数**（并列取大）。

## 3. 层高

必须先问用户，默认值：

| 用地类型 | 层高 |
| --- | --- |
| 住宅（2023 代码 `07` 开头 / GB50137 `R` 开头） | 3.0 m |
| 已识别非住宅 | 4.5 m |
| 用地代码未识别 | 3.0 m |
| 混合用地（`100104+0909`） | 按**首段**代码判定，报告注明「混合用地按首段」 |

- 未给 `--floor-height` 也未给 `--floor-height-policy` → 输出 `floor_height` 确认项（退出码 3），不得闷头按 3m 出表；
- `--floor-height 3.0` 全局统一；
- `--floor-height-policy auto` 接受上述默认；
- 层高同时影响**容积率与体块高度**，改层高必须重跑两份成果。

## 3.1 图上完全没有层数标注时

实测常见：一张方案图只有 `30m`/`24m` 这类道路宽度文字，没有任何 `砼N`/`NF`。此时按 1 层算出来的
「容积率」等于建筑密度，不能当容积率交付。必须先问用户层数，再用命令行补：

```bash
# 按图层分别给层数（推荐，塔楼与裙房分开）
python scripts/up.py far --file 方案.dxf --unit m \
  --building-layers "1-202512塔楼,1-202512裙房" \
  --floors-by-layer "1-202512塔楼=12,1-202512裙房=3" --floor-height-policy auto

# 全图统一层数
python scripts/up.py far --file 方案.dxf --floors 6 --floor-height-policy auto
```

优先级：图上文字层数 > `--floors-by-layer` > `--floors` > 默认 1 层。
报告「层数来源」会写明每个图层用了多少层、命令行补了多少栋。

## 3.2 单位必须先验，别信 $INSUNITS

实测绘制的方案图经常把米制标成 `$INSUNITS=4`（毫米）。后果是建筑面积被乘 1e-6，
全部低于 10 ㎡ 阈值而被过滤，最后报「没有建筑」。判断方法：看规划范围包围盒跨度——
2 km 量级是米，2e6 量级才是毫米。米制图标成毫米时显式加 `--unit m`。

## 4. 标准分层流程

```bash
# 0. 先确认图层（建筑 / 用地 / 层数标注）
python scripts/up.py massing --file 总图.dxf --confirm-layers

# 1. 测算 + 建模，一次取数
python scripts/up.py massing --file 总图.dxf \
  --height-layers "BZ-建筑层数" --floor-height-policy auto \
  --task all --out 容积率测算表.md

# 2. 只算容积率（不动模型）
python scripts/up.py far --file 总图.dxf --height-layers "BZ-建筑层数" --floor-height 3.0 --task measure

# 3. 只批量建模
python scripts/up.py extrude --source com --task extrude --extrude-format solid
```

## 4.1 图层必须由用户拍板（两级确认）

**名字相似不代表正确**，这是本子技能最容易出错的地方：

| 陷阱 | 实例 | 后果 |
| --- | --- | --- |
| 空图层 | `选取现状建筑` 名字最像，但 0 个图元 | 选它 = 0 栋建筑 |
| 影像底图 | `建筑肌理0429` / `总平面0422` / `用地图片0422` 都是 `IMAGE` | 无法量算、无法拉伸 |
| 近义分层 | 真建筑在 `1-202512塔楼` / `1-202512裙房`，名字不含「建筑」 | 只按名字识别会完全漏掉 |
| 近义范围 | `规划范围`（含影像、非闭合）、`核心区设计范围线`、`街区划分` | 范围取错 → 容积率全错 |
| 未登记代码 | `1-202512塔楼` 的 `202512`、`012-甲2 ...lyq` | 建筑被算成用地，或用地漏算 |

**第一级：选图层。** 未显式给 `--building-layers/--parcel-layers/--scope-layers` 且存在下列任一情况时，
必须输出 `layer_assignment` 确认项（退出码 3），不得按默认值直接算：

- 建筑组命中 ≠ 1 个图层；
- 有「像建筑」的图层不在建筑组（`塔楼/裙房/主楼/楼/栋/厂房/写字楼` 等）；
- ≥ 2 个图层都含闭合轮廓（可能是塔楼/裙房分开表达）；
- 有候选是空图层；
- 范围组命中 ≠ 1 个，或有「像范围」的图层（`范围/界线/边界/管控线`）；
- 范围候选里有影像底图；
- 有图层像用地但代码未登记。

确认项 detail 必须给出每个候选的：图元数、闭合面数、面积、是否影像、是否空图层、备注。
`--accept-layers` 才允许跳过；`--layer-map` 写入确认结果后重跑可复用。

**第二级：单图层内部选建筑面。** 建筑组为空时，用 `--auto-detect-buildings` 的几何+文字候选，
与第一级不得混为一谈。

## 5. 单图层 / 非标准图流程（重点）

判定：`layer_spec` 建筑组为空 → 判为"疑似单图层"，**必须先告知偏差风险**：

> 本图未识别到建筑图层，所有要素可能位于同一图层。建筑轮廓只能靠几何形态与文字标注启发式推断，
> 提取结果可能存在较大偏差，必须人工核对后再使用。

候选打分（`assets/massing_rules.json` 的 `single_layer`）：

| 证据 | 处理 |
| --- | --- |
| 内含 `砼\d*` / `\d+F` / `\d+层` / `H=` 文字 | +3（最强证据，层数标注就在建筑里） |
| 内含其他短文字 | +1 |
| 顶点 4–20 个 | +1 |
| 落在用地地块内 | +1 |
| 与用地地块面基本重合（IoU ≥ 0.98） | -3（是地块线，不是建筑） |
| 包含 ≥2 个候选面，或面积 > 3000 ㎡ 且包含候选面 | 剔除（父面 = 地块/范围/图框） |
| 面积 < 10 ㎡ 或 > 20000 ㎡ | 剔除 |
| 长宽比 > 20 | 剔除（带状要素） |
| 自交 / 面积 0 | 剔除 |

- 默认**不启用**自动识别，必须用户确认后加 `--auto-detect-buildings`；
- 识别结果需人工复核，报告首页常驻偏差提示；
- 单图层通常也**没有独立用地图层**：容积率算不了，改用 `--no-parcel` 只出全图建筑量合计
  （建筑量、层数、高度照常出，容积率与密度标「不适用」）。

```bash
# 确认后：启用候选识别 + 无用地边界，只出全图建筑量
python scripts/up.py massing --file 地形图.dxf --auto-detect-buildings --no-parcel \
  --floor-height-policy auto --task measure --out 建筑量汇总.md
```

## 6. 建筑归属地块

- 默认**代表点整栋归属**（与退线子技能 `parcel_height` 同一判据）；
- 一栋楼跨两个地块（本地块占比 < 95%）→ 出 `cross_parcel_building` 异常，**必须告知用户**；
- `--cross-parcel clip` 按相交面积分摊，`exclude` 整栋不计入；
- 不在任何地块内的建筑 → "未计入任何地块指标"异常，给句柄。

## 6.1 重复表达去重（同层「填充 + 多段线」）

同一图层里一栋建筑常常既有 HATCH 又有闭合 LWPOLYLINE，两种处理后果完全不同：

| 方式 | 结果 |
| --- | --- |
| `source="auto"`（图层级跳过） | 该层只要有任意填充，整层多段线全部丢弃——「部分建筑只用多段线画」时会**整批漏算** |
| `source="both"` + `dedupe=True`（几何级去重） | 两种表达都收，按几何重合去重，同一轮廓只算一次 |

判据（两条同时成立才判重复）：

- 小面积轮廓被大轮廓覆盖 ≥ 90%；
- 面积比 ≥ 60%（允许填充扣了内院、或有阳台差异导致面积偏小）。

保留优先级：**填充 > 多段线**，同类型保留面积大的。被丢弃的那条进异常清单
（`building_duplicate`），写明「与 hatch「xxx」重复表达同一轮廓，未重复计入」，报告可解释
「图上 4 个轮廓为什么只算了 3 栋」。

适用范围：`massing` / `setback` / `fivelines` 的建筑采集统一 `both + dedupe=True`；
`balance` 的地块仍用 `auto`（地块面通常只有一种表达，且已有多轮回归锁定）。

## 6.2 规划范围裁剪

容积率只对规划范围内用地有意义，默认按含「规划范围/设计范围」的图层裁剪（排除图片、影像、图框）：

```bash
--scope-layers "000-规划范围"   # 显式指定
--scope-mode none               # 整图测算（复核用，不作交付口径）
```

- 地块：取与范围的相交几何，面积按相交重算；
- 建筑：代表点在范围内才计入，范围外进「剔除」计数；
- 报告「规划范围」写明用哪个图层、剔除多少地块与建筑。

未登记代码的图层不得当地块：`1-202512塔楼` 的 `202512` 会被误读成用地代码，
`总平面0422` 的 `0422` 同理。脚本只收「识别出真实用地代码」的图层，其余输出
`unregistered_code` 确认项（退出码 3），由用户判断是写错图层名还是真用地未登记：

| 用户答复 | 参数 | 效果 |
| --- | --- | --- |
| 图层名写错 | 改图层名后重跑 | 不写入配置 |
| 确认是新增用地性质 | 先登记 `scripts/add_classification_node.py`，再重跑 | 按新代码归类 |
| 归入已有类目 | `--unregistered-code "C=map:目标代码"` | 报告说明记录归属 |
| 本次不处理 | `--unregistered-code "C=skip"` | 该层面积仍进表、用地代码留空标「未识别」，报告标需复核 |

静默剔除会让这些地块的面积从分母里消失，容积率被系统性高估，因此**只要像用地就必问**。

## 6.3 混合用地（合成代码）

图层名形如 `100104+0909新型工业+商业服务业混合用地` 时，与平衡表同一口径：

- 用地代码显示**合成代码** `100104+0909`（地块表、超限清单、`BZ-容积率` 标注三处一致）；
- **面积按整块几何只计量一次**，不按段拆分，绝不重复计容；
- 层高按**首段代码**（`100104` → 非住宅 4.5m），报告「层高」列会注明「混合用地按首段」；
- 混合段只认「代码点名」与「分类表中文原名」，纯中文描述性段落（如「研发设计混合用地」）不算独立一段；
- 某段既非表内代码也非表内名称 → `hybrid_unresolved` 确认项（退出码 3），
  选「只按首段统计」需 `--ignore-hybrid-unresolved`，报告标需复核、不得直接交付；
- 报告固定有「五、混合用地与用地性质确认」一节：`图层 → 合成代码 → 各段代码 → 未解析段`，
  交付时逐条对照；`--mapping` / `--classification` 可换自定义映射与分类树。

## 6.4 地块筛选（哪些地块编号、出指标）

默认 `--parcel-filter auto`，按「有没有识别到用地性质」分两种口径：

| 地块情况 | 编号 + 容积率/建筑密度 | 处理 |
| --- | --- | --- |
| 性质已识别，一级类 ∈ 建设用地且非绿地（2023：06–13、15、16） | ✅ | 无建筑也出（FAR=0） |
| 性质已识别，一级类 = 14 绿地与开敞空间用地（GB 50137 为 G） | ❌ | 默认不出指标，进 `parcel_filtered` 写明「绿地」 |
| 性质已识别，一级类 ∉ 建设用地（01–05、17–24） | ❌ | 进 `parcel_filtered` 清单，写面积与原因 |
| 性质未识别，有建筑落位 | ✅ | 用地代码列显示「未识别」 |
| 性质未识别，无建筑落位 | ❌ | 进 `parcel_filtered` 清单 |

- 建设用地范围取分类表 `balance_groups.construction`（2023 为 06–16，GB 50137 为 R/A/B/M/W/S/U/G），**不写死数字**；
- 默认排除的大类取配置 `massing_rules.json → parcel_filter.exclude_classes`（缺省 `["14", "G"]`）。**这条只影响本子技能的编号与指标，平衡表里绿地仍计入建设用地面积**；
- 筛选在算完归属、编号之前做，所以**序号会按保留地块重排**；
- 剔除地块上的建筑标 `excluded`，单列 `building_on_filtered_parcel` 异常，不参与计容也不进拉伸；
- 报告开头「地块筛选」一行 + 「校验」节的「参与测算地块 / 剔除地块」两行必须写清，JSON 见 `parcel_filter`（含 `dropped` 明细）；
- 用户另有要求时覆盖：`--parcel-filter all`（旧口径，全部编号出指标）/ `construction`（只按建设用地，含绿地）/ `built`（只按有建筑落位）；细调用 `--parcel-classes "07,08,09"`（白名单，优先级最高）或 `--parcel-exclude-classes "14,15"`（在 auto 基础上追加排除）。

## 7. 闭合校验与批量拉伸

EXTRUDE 对闭合极其敏感，先三态判定：

| 状态 | 判据 | 处理 |
| --- | --- | --- |
| 可直接拉伸 | CAD 自报闭合 / 填充边界 / 线段缝合 | 拉伸 |
| 需人工复核 | 首尾容差吸附（原图其实有缺口） | 拉伸，但进「需人工闭合」清单 |
| 不可拉伸 | 未闭合、自交、点数不足、面积 0 | 不拉伸，进异常清单给句柄 |

两条路线，能力不对等，必须写明：

| 通道 | 产出 | 说明 |
| --- | --- | --- |
| COM（有 CAD） | 真 `3DSOLID`（`AddRegion` → `AddExtrudedSolid`） | 可用布尔运算 |
| DXF（无 CAD） | 顶面 + 侧面 `3DFACE` 体块网格 | **不是 ACIS 实体**，只作体块示意 |

`--extrude-format`：`solid` / `mesh` / `none` / `ask`（默认）。
`ask` 时：有 CAD 直接出实体；无 CAD **必须先问用户**出体块网格还是只出清单，不得静默降级。

### 7.1 成果分层（塔楼 / 裙房）——执行前必问

体块写一个图层还是分塔楼/裙房两个图层，取决于**图上有没有区分**，而这件事只能由用户拍板：

| 图上情况 | 判据 | 必须怎么问 |
| --- | --- | --- |
| 已区分塔楼/裙房 | 参与建模的建筑图层里同时存在含 `塔楼/主楼` 与 `裙房/裙楼` 的层 | 「已区分，体块是否也分两个图层？」三选一：按图层分 / 合并到单层 / 改按高度阈值重分 |
| 未区分 | 单层，或多层但层名不含塔楼/裙房（只命中一半也算未区分） | 「是否按高度分层（>24m 塔楼 / ≤24m 裙房）？」二选一（另可自定义阈值） |

- 确认项 code：`extrude_layering`（退出码 3）；detail 必须给每个建筑图层的栋数、基底面积、高度区间、命中关键字、阈值与拟用图层名；
- 归层优先级：**源图层点名（塔楼/裙房） > 高度阈值 > 裙房兜底**；单栋的判定依据要写进报告第七节；
- 阈值默认 24 m（`massing_rules.json → extrude.tower_height_m`），`--tower-height` 可改；
- **阈值判的是「拉伸高度 = 层数 × 层高」**（简单计容），不是报建高度，报告必须带这句；
- 图层名默认 `<体块层>-塔楼` / `<体块层>-裙房`（后缀取 `extrude.layer_suffix`），`--extrude-layer-tower/-podium` 可指定；
- `--extrude-layering ask|keep|by-height|none`（默认 ask）：`keep` 但图上实际没分时**自动回退 by-height 并在报告注明**，不得假装按图层分；
- 只建模（`--task extrude`）与测算+建模（`all`）都会问；纯测算、`--dry-run`、`--extrude-format none` 不问。

其它约定：
- 拉伸高度 = 层数 × 该地块层高；
- 只拉伸成功归属到地块的建筑（`excluded` 的跨地块建筑不拉伸）；
- 内环（洞）默认忽略并提示（LWPOLYLINE 表达不了洞）；
- 批量分块（默认每 100 栋）续命看门狗，单栋失败不中断整批。

## 8. 成果图层与标注

| 图层 | 内容 | 默认 |
| --- | --- | --- |
| `BZ-容积率` | `编号-用地代码-容积率`，如 `001-070102-FAR2.10`、`017-100104+0909-FAR4.51` | 模板 `{seq}-{code}-FAR{far:.2f}`；`{code}` 为合成代码，未解析段标 `?` |
| `JZ-体块` | 拉伸体块 / 体块网格（不分层时） | `massing_rules.json` 可改 |
| `JZ-体块-塔楼` | 分层时塔楼体块（源层点名塔楼或高度 > 阈值） | 后缀取 `extrude.layer_suffix` |
| `JZ-体块-裙房` | 分层时裙房体块（含 ≤ 阈值与兜底项） | 同上 |

编号与地块编号子技能共用同一套排序与模板引擎（`{seq:03d}` + `order_records`），不另写一套。

地块表并列给「建筑密度」与「建筑覆盖率」两列，两者同义（基底面积 ÷ 用地面积），
并列是为了让用户直接取用习惯叫法，不是两个指标。分级汇总时综合建筑覆盖率在「校验」节给出。

容积率超限：`--far-limit` 默认 6.0，超过的地块按容积率降序单列「八、容积率超限地块」，
JSON 里是 `far_limit` 与 `far_exceed`；`--far-limit 0` 关闭该清单。

报告章节固定为：一、测算说明 → 二、地块容积率与建筑密度 → 三、建筑清单 → 四、校验
→ 五、混合用地与用地性质确认 → 六、异常与待复核清单 → 七、三维拉伸成果 → 八、容积率超限地块。

## 9. 确认项（退出码 3）

| code | 触发条件 | 必须原样转给用户 |
| --- | --- | --- |
| `layer_assignment` | `--confirm-layers`，或未指定图层且存在歧义 | 建筑/用地/范围候选（图元数、闭合面、面积、是否影像、是否空图层）+ 歧义原因；`--accept-layers` 可跳过 |
| `single_layer_scene` | 建筑组为空且未 `--auto-detect-buildings` | 偏差风险声明 + 候选表 |
| `floor_height` | 未给 `--floor-height` 与 `--floor-height-policy` | 住宅 3.0 / 非住宅 4.5 / 未识别 3.0 |
| `no_parcel` | 无可用地边界 | 指定图层 / 只出全图汇总（`--no-parcel`）/ 先修图 |
| `extrude_format` | 无 CAD 且 `--extrude-format ask` | 体块网格 / 只出清单 / 换机器重跑 |
| `extrude_layering` | 建模任务且未给 `--extrude-layering` | 已区分塔楼/裙房 → 分图层 / 合并单层 / 改按 24m；未区分 → 按 24m 分层 / 不分层（detail 带各层栋数与高度区间） |

## 10. 校验与复核话术

必查：
- 建筑密度是否 > 100%（基底面积超过用地面积 → 图层或归属错了）；
- 默认 1 层的建筑数与占比（占比高说明层数标注缺失，容积率偏低）；
- 跨地块建筑条数；
- 未闭合 / 自交建筑条数（这些没有模型）；
- 容积率明显异常（如 < 0.1 或 > 10）先怀疑归属与层数，不要直接交付。

交付时说清六件事：任务（测算/建模/两者）、建筑量口径（简单计容）、采用层高与来源、
默认 1 层几栋、跨界建筑怎么处理、成果是 DWG 还是 DXF（以及为什么）、模型是实体还是体块网格。
带句柄的异常必须附定位方法。

## 11. 与其它子技能的关系

- 层数解析下沉在 `lib/building_class.py`（`parse_floor_info` / `attach_floors`），退线仍用 `parse_height_text`，
  两者口径不同（退线抓不到高度就两条线都出，测算抓不到层数就按 1 层），**不得互相替换**；
- `buildings.json` 由本子技能产出，退线可复用（第二阶段），避免同一栋楼两处层数不一致；
- 用地代码解析仍走 `core.classify.LayerMapper`，本子技能不维护代码表。
