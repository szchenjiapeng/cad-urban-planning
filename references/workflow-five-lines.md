# 子技能 N4：城市控制线（原「城市五线」）

触发词：控制线、城市控制线、五线、城市五线、红线、绿线、蓝线、紫线、黄线、五线图、管制线。

## 1. 控制线口径

| 线 | 含义 | 默认派生来源（2023） |
| --- | --- | --- |
| 红线 | 道路红线 | `layer:道路红线` / `layer:DL-` |
| 绿线 | 绿地控制线 | `code:1401,1402,1403`（公园/防护绿地、广场） |
| 蓝线 | 水域控制线 | `code:17`（陆地水域）+ 水系/河道图层 |
| 黄线 | 市政基础设施控制线 | `code:13`（公用设施）+ 市政设施图层 |
| 紫线 | 历史文化保护线 | **默认人工**，只做规范化与校验，不自动猜 |

GB 50137 口径：绿线 `G1/G2/G3`、黄线 `U`、红线 `S1`；蓝线该配置未收录水域代码，按图层名取，
成果里必须写「需复核」。

### 口径来源必须先确认（硬性）

`assets/five_lines.json` 的 `_status` 为内置通用默认值，线位、缓冲距离、是否成图都由它决定，不能照搬。用默认配置且未加 `--accept-default-rules` 时，脚本先抛 `five_lines_rules_source` 确认项（退出码 3）：

| 情形 | 处理 |
| --- | --- |
| 按内置默认值执行 | 加 `--accept-default-rules`，报告注明「按内置默认值，未经院内标准校准」 |
| 逐项指定 | `--line` / `--buffer` / `--protect` / `--enable-blue` 等覆盖 |
| 院内标准 | `--config 标准.json`，报告记录文件路径 |

配合 `--rules-note "XX市…规定 第4.2条"` 把依据写进报告与 JSON（`config_source`）。确认项 `detail` 会列出各条线的来源/缓冲/是否成图与校验阈值，供用户核对。

## 2. 逐条指定来源（推荐）

```bash
python scripts/up.py fivelines --file 总图.dxf \
  --line "红线=layer:道路红线" \
  --line "绿线=code:1401,1402,1403" \
  --line "蓝线=code:17;layer:水系" \
  --line "黄线=code:13;layer:市政设施" \
  --line "紫线=layer:历史保护" \
  --out 控制线成果.md
```

- 一条线多个来源用**分号**分隔；
- `code:` 内部用**逗号**分隔多个代码，支持一级/二级前缀（`13` 命中 `1301`）；
- `layer:` 支持关键词或通配符（`DL-*`）；
- `manual` 表示人工绘制，脚本跳过生成。

## 3. 参数

| 参数 | 说明 |
| --- | --- |
| `--line` | 逐条线指定来源，可重复 |
| `--auto on\|off` | 是否叠加配置里的默认口径，默认 on |
| `--config` | 控制线配置，默认 `assets/five_lines.json`（院内/地方标准请指定本参数） |
| `--accept-default-rules` | 明确同意按内置默认值口径执行；不加且配置仍为默认值时输出 `five_lines_rules_source` 确认项 |
| `--rules-note` | 口径依据说明，写入报告与 JSON |
| `--buffer` | 逐线缓冲，`"绿线=10,蓝线=30"`（米） |
| `--building-layers` | 用于「蓝线内建筑」校验 |
| `--check-tolerance` | 控制线互交判定容差（㎡），默认 1 |
| `--bridge-mode connect\|seal` | 蓝线桥位口径：`connect`=A 贯通（默认）、`seal`=B 保持断开；**不指定时遇歧义先询问用户** |
| `--bridge-gap` | 桥宽上限（m），默认 60；**超过该值的桥位上下游不会连接**。不指定时会先量出实测最远配对距离再询问用户 |
| `--standard auto\|2023\|gb50137` | 分类标准，auto 时按图层判标 |

## 4. 生成规则

1. 来源图层取闭合面（填充优先，多段线回退）；
2. 只有开放线时用 `polygonize` 缝合成面，并在报告里提示「已缝合，请复核」；
3. 同一线内多块面先 `union`，再按 `--buffer` 外扩；
4. 写入标准图层（`KZX-红线` 等），颜色与线型取 `layer_spec.control_lines`；
5. 紫线等 `manual` 线只做存在性与命名校验。

### 蓝线桥位

- 判据：与道路红线共线的边界段，两端能与**另一块水域**的岸线端点配对、连线穿过红线走廊且与横切边近乎垂直，才判为真断口并两点直连；贴河边（对岸没有水域）一律保留。
- 桥位口径：`A 贯通（connect，默认）` / `B 保持断开（seal）`。
- **桥宽上限必须先问用户**：指定蓝线且未给 `--bridge-gap` 时，脚本先用 `blue_line.measure_bridge_gap()` 量出本图「水域面最远配对距离」，再输出 `blue_bridge_gap` 确认项（退出码 3）：默认 60 m，给出建议值（实测最远 ×1.2 向上取整到 10 m），并明确提醒**超过该值的桥位上下游不会连接**。
- **认不出断口时不得自行决定**：脚本置 `ambiguous` 并输出 `blue_bridge_mode` 确认项，必须问用户，默认 A；确认后按 `detail.rerun_A` / `detail.rerun_B` 给出的参数重跑。
- 口径换算提示：按红线间距量取通常大于水域面间距（河岸还压着绿带），用户给的数比实测大时按用户的数跑即可。
- 常见触发场景：水域填充截到道路红线为止（断口边压在红线上、一侧是道路）；河道宽度大于 `--bridge-gap`。

## 5. 校验

| 校验 | 判定 |
| --- | --- |
| 蓝线内建筑 | 建筑与蓝线范围相交 → 冲突（给建筑句柄） |
| 绿线面积偏差 | 与绿地类用地面积偏差 > 5% → 冲突 |
| 红线面积偏差 | 与道路用地（1207 / S1）面积偏差 > 5% → 冲突 |
| 控制线互交 | 两线重叠面积 > 容差 → 冲突 |
| 线未闭合 | 无法缝合成面 → 该线跳过并说明原因 |

## 6. 成果

- **默认出 DWG 新副本** `<原名>_控制线.dwg`（AutoCAD 2018 格式），原图不动；
- 本机无法执行 CAD（无 `accoreconsole.exe`）时回退 `<原名>_控制线.dxf`，回退原因写进报告与 JSON（`copy_note`）；
- `--copy-out 成果.dwg` 可改路径/格式（扩展名优先）；`--no-write-back` 只出报告不导图；
- 报告：控制线成果表（线名/图层/来源/面积/写入线段）+ 校验与冲突清单；
- JSON 摘要含逐线来源图层、`manual_lines`、`copy_out` / `copy_format` / `copy_note`。

## 7. 注意

- 城市控制线（习惯称「五线」）是**管制线**，派生结果只作为初稿；紫线、黄线涉及具体设施边界时必须人工核对。
- 红线若同时存在「道路红线图层」与「1207 道路用地」，优先取红线图层，并做面积偏差校验；
- 缓冲距离为 0 时生成的是贴边线，不等于「管制范围外扩」，需要外扩必须显式给 `--buffer`。
- **桥位口径必须问用户，默认 A（贯通）**：凡是「与道路共线的河口线识别不出断口」「桥位上下游岸线配不上对」的情况，脚本以退出码 3 停下来问，禁止默认按 B 或静默输出分段边界。A/B 的几何差别：A 删桥位横切边并跨路连成连续河口线；B 保留横切边，两岸各自封口。
- **桥宽上限必须问用户，默认 60 m**：执行前先量实测最远配对距离，问的时候必须写清「超过该值将不会连接」；用户给的数（常按红线间距量取）大于实测值是正常的，按用户的数跑。
- 面积偏差校验的基准已按「先去重叠再求面积」计（同一片绿地常被「用地填充 + 地块线」重复表达）；无建筑图层时不做蓝线内建筑校验，避免把全图地块误判为建筑。
